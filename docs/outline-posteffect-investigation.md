# 現在の輪郭線描画と輪郭専用ポストエフェクトの調査

調査日: 2026-09-08

この文書は実装前の調査記録。後続の実装・実機検証結果は [輪郭の色にじみ](outline-color.md) を参照。

## 結論

輪郭線だけにポストエフェクトを掛けることは可能。ただし、現在の画面には輪郭線が通常描画と一緒に合成されているため、専用の輪郭マスクを追加する必要がある。実装・画面比較は未実施で、今回はゲーム設定を変更していない。

今回の「ブルームの広がりを 0 にして輪郭に色を乗せる」用途には、既存の輪郭を対象にした明度・彩度補正や、近傍の肌・髪・背景の色を混ぜる処理が適している。背景のブルームとは独立して調整できる。

## 実物から確認できた描画構造

COM3D2 MCP で実行中の材質とパス名を取得し、ゲームの `COM3D2x64_Data/resources.assets` に収録された Shader の構造も UnityPy で読み取った。

| 対象 | 実行中のシェーダー | 実行時に取得したパス |
|---|---|---|
| 顔・肌・衣装 | `CM3D2/Toony_Lighted_Outline_Tex` | `FORWARD` × 2、`OUTLINE` × 2 |
| 髪 | `CM3D2/Toony_Lighted_Hair_Outline_Tex` | `FORWARD` × 2、`OUTLINE` × 2 |
| 口の材質 | `CM3D2/Toony_Lighted_Outline` | `FORWARD` × 2、`OUTLINE` × 2 |

これは材質の専用パスで描く輪郭線である。PostEffects の「輪郭検出」機能とは別の仕組み。

収録シェーダーの髪用定義は、`CM3D2/Toony_Lighted_Hair/FORWARD` と `CM3D2/Outline_Tex/OUTLINE` を参照している。顔・衣装系と同名の定義は複数あり、`Outline_Tex` を参照するものと `Outline_Tex_Texwidth` を参照するものがあった。同名だけでは実行中のアセットとの完全な対応までは確定できない。

両方の輪郭シェーダーで、次を確認した。

- `Cull Front`: 表面を除外し、裏面を描画する。
- `ZTest LEqual`、`ZWrite On`: 奥行きを判定し、深度にも書き込む。
- `OUTLINE` の内訳は `ForwardBase` と `ForwardAdd`。後者は加算合成で、追加ライト向けのパス。
- `_OutlineColor`、`_OutlineWidth` に加えて `_OutlineTex`、`_OutlineToonRamp`、`_CutoffTex` が存在する。
- `Outline_Tex_Texwidth` には `_OutlineWidthTex` も存在する。

裏面描画と線幅パラメーターの構成は、モデルを少し膨らませた裏面のはみ出しを線として見せる「背面法／反転ハル方式」に整合する。ただし、コンパイル済み頂点プログラムの変位計算そのものは逆アセンブルしておらず、押し出す座標系や距離補正の式までは未確認。

実行中の顔と髪の `_OutlineTex` には RenderTexture が設定されている。したがって `_OutlineColor` だけでは最終的な輪郭色を説明できない。以前の回答で挙げた茶色は材質パラメーターの値であり、画面の線の最終色そのものではない。

## 輪郭だけを処理する設計

基本の流れは次のとおり。

1. 通常どおりシーンを描く。
2. 同じ輪郭形状と遮蔽条件を使って、「実際に見えている輪郭線」のマスクを別のテクスチャに描く。
3. 画面の色に対して色補正・近傍色の混合・にじみなどを計算する。
4. マスクの部分だけに処理結果を合成する。

既存の `OUTLINE` パスを利用した別描画、または輪郭描画時にステンシル／別の出力へ印を残す方式が候補。既存パスの色出力は黒にもなるため、単に黒背景へ描いて明るさをマスク扱いすると黒い輪郭を検出できない。輪郭の色と、輪郭が存在するかを示す情報は分けて取得する必要がある。

専用描画では本体・背景による遮蔽も再現する。深度なしで裏面だけを描くと、線ではなくモデルの広い領域が出てしまう。また、現行の輪郭自体が深度を書いているので、深度の流用時点や比較条件も確認が必要。

既存の `CharacterMask` はキャラ全体の領域を示すもので、輪郭線そのもののマスクではない。境界を細く抜くだけでは、髪が顔に重なる部分などの内部の輪郭を拾えず、実際の線幅とも一致しない。

## 今の用途に合う効果

| 効果 | 得られる見た目 |
|---|---|
| 輪郭の明度・彩度・色相補正 | 元の線の色を保ちながら、明るくしたり鮮やかにしたりする |
| 周囲の色を輪郭へ混ぜる | 肌や髪などの近傍の色が線へ乗る。混合量・参照距離を独立調整できる |
| 輪郭だけへの Screen／加算合成 | 細い線を保ちつつ、色や明るさを足す |
| 輪郭から作る小さなグロー | 線の周囲へ光をにじませる。黒い線は別途着色・発光化が必要 |

最初の試作は「正確な輪郭マスク＋近傍色の混合」が有力。単純なブルームは暗い輪郭自体から光を作れないため、現在の見た目が周囲の明部の回り込みによるものなら、輪郭だけをブルーム処理しても同じ結果にはならない。

広がり 0 でも、ブルーム内部の縮小・拡大などで近傍画素が混ざる可能性がある。今回の調査ではブルームの有無を切り替えて比較していないため、現在の色乗りの原因の割合までは確定していない。

## 実装時に確認すべき点

- 顔・髪・衣装の各線とマスクが一致するか。
- 髪と顔の重なり、背景による遮蔽、カットアウト部分で余分な線が出ないか。
- 細い線のアンチエイリアスと解像度によるちらつき。
- 髪は実行時の描画キューが 980、顔・衣装系は 2000 だったため、標準の描画順を前提にしないこと。
- 輪郭色の補正をブルームやトーンマッピングの前後どちらに置くか。

完全な既存線の再現には専用マスクの検証が必要だが、輪郭だけを加工する設計は十分成立する。
