# キャラ・背景ブルーム

標準・シネマティック・フィルミックに分離モードを追加した。
キャラ側の有効状態・強度・しきい値・広がりを `separation` に保存し、
背景側の強度などは既存フィールドを使用する。品質、色、レンズフレア、光条などは共有する。
`separation.enabled` の既定値は false なので、従来のプリセットでは描画経路を変えない。

## 描画

標準ブルームのHDRはキャラと背景で共通。「共通 HDR」でAuto・On・Offを選択する。
従来のhdr設定を使用し、一時的に追加したcharacterHdrを含むXMLも読み込める。
そのキャラ専用値は無視し、従来のhdr値を両領域に適用する。
強度・しきい値・広がり・有効状態の分離は維持する。
共通HDRの保存復元、旧XMLの互換性を両版のテストで確認済み。
新しいUIと修正版DLLの実機動作確認は再起動後に必要。

`OnPreCull` で共有キャラマスクを要求する。分離要求時だけ背景の不透明面と
アルファテスト面の深度を先に描き、壁に隠れたキャラを除外する。
キャラは既存と同じ `Charactor` レイヤーで分類し、メインカメラのカリングマスクも反映する。
髪・まつ毛などのキャラ側アルファ形状は既存マスクと同じく全面扱いで、半透明の背景は遮蔽物に含めない。

`SeparatedBloomEffect` は元画像を相補的なキャラ入力・背景入力へ分け、
それぞれを既存ブルームで処理して和を出力する。無効な側はマスク済み入力をそのまま返す。
合成後は再マスクしないので、輪郭外のにじみを保つ。アルファは元画像を引き継ぐ。
中間RTは元画像と同じフォーマットを使用し、HDR値をシェーダーでクランプしない。

手動描画対象の元コンポーネントは無効にして二重描画を防ぐ。
2.5内蔵ブルームの非公開 `OnRenderImage` はカメラごとに一度作るデリゲートで呼ぶ。
分離用コンポーネントはカメラ末尾に追加するため、分離を切り替えると他のエフェクトとの
適用順が変わることがある。無効化時は既存コントローラの復元処理へ戻す。

## 検証

- COM3D2.5 / COM3D2 (2.0) の Release ビルド成功。
- 両版で3種類の設定XMLの往復、旧XMLの読込、設定インスタンスの独立性を検証。
- Unity 2022.3.62f2 の GPU 描画で HDR抽出、マスク相補性、無効時の元画像復元、
  色・アルファ保持、輪郭外の光の保持、背景遮蔽を検証。
- COM3D2.5 用の `posteffects` バンドルを更新。
- Unity 5.6.4f1 はライセンス未認証のため、2.0用バンドルの生成とGPU検証は未実施。
  2.0版で分離を使用するには、認証済みUnity 5.6で同じシェーダーをビルドする必要がある。
- COM3D2.5の実機で、背景ブルームの切替とHDR判定による変色をMCP経由で検証（下記）。

GPU検証は `UnityProject` を開き、`PostEffects > Validate Separated Bloom` を実行する。
batchmode では `-executeMethod ValidateSeparatedBloom.Run` を指定する。
GPUを使用するため `-nographics` は指定しない。

XML検証は `source/Tests/BloomPresetSmoke.cs` を .NET Framework の `csc` でコンパイルし、
生成された exe にプラグインDLLのパスと該当ゲームの `COM3D2x64_Data/Managed` を渡す。

## この作業環境への反映

COM3D2.5用の成果物は `UnityInjector (COM3D2.5)` に配置済み。
分離機能は現在のゲームに読み込まれている。下記のHDR判定修正版DLLは反映待ち。
ゲーム終了後に `output/ApplySeparatedBloom.cmd` を実行すると、`.env` の `COM3D25_DIR` へ
DLLとシェーダーをバックアップ付きで反映する。

## HDR入力がオレンジに変わる問題（2026-09-08）

MCPで実機の背景ブルームを切り替え、画面上部が青紫からオレンジになる現象を再現した。
CameraMain.allowHDR は false だが、分離ブルームへの入力は ARGBHalf だった。
内蔵BloomのAuto判定はカメラ設定も参照するため、この入力をLDRとしてScreen合成していた。
Screen合成の `1 - (1 - bloom) * (1 - source)` に1を超えるHDR値が入り、色成分が減少する。

- 元の設定：HDR=Auto、Screen、背景強度=5、しきい値=0.5714285、フレア強度=0。
- 同じ位置の入力RGB=(0.704, 0.450, 1.839)、出力RGB=(0.901, 0.450, 0.046)。青が失われた。
- HDR=Onで再検証：入力RGB=(0.703, 0.450, 1.835)、出力RGB=(1.366, 0.450, 8.172)。反転は消えた。
- 撮影時刻による入力の小差はあるが、背景ブルーム無効・Screen・Add・HDR Onの画面を比較済み。

修正は分離描画のAuto判定でARGBHalf/ARGBFloat入力をHDRとして扱う。
描画後はコンポーネントの元のHDR設定に戻し、保存設定を変更しない。
明示的なHDR Offは維持する。HDR入力でOffとScreenを併用すると変色し得る。
両ゲーム版のReleaseビルド成功。シェーダー変更は不要。
修正版DLL自体の実機読込はゲーム再起動後に必要。
現在のゲームでは回避策としてHDRをOnに変更し、背景有効状態とブレンド設定は検証前に戻した。
